# 对话报告的结构（默认产出）

默认路径下**不落文件**——四项信息在对话里报告完，交付即完成。本文件给结构与措辞。

## 为什么默认不落文件

未经要求不新建成品文档（提示词 §7.1）。用户多数时候只是想知道「这视频讲了啥」，
要的是答案，不是一个文件。文件是要占地方的：得命名、得选落点、得考虑要不要入库。
**报告本身就是交付物。**

要笔记 / 文档 / Markdown 时是另一回事——那是用户明确要文件，走 `note-template.md`。

## 报告结构

用四段，对应四项抓取。**不要**写成文件模板的缩略版——那是另一种东西。

```markdown
{BV号}｜{UP主}｜{时长}｜{播放等关键数据}

{视频标题}

**视频简介**
{原样或摘要简介。简介常含视频正文没有的信息（课程目录、资料说明、外部链接），
是独立价值来源。简介为空就写「无简介」。}

**内容要点**
{按语义分节，不是逐字稿。保留数字、参数、结论；删掉口语填充。}
{用中文数字分节（一、二、三）或小标题，跟着视频的主题切换走。}
{代码、配置、命令进代码块。对比性内容用表格。}

**评论情况**
{实抓数 / 页面声明数 / 差值（非零则说明来自已删除或隐藏的评论）。}
{讨论质量：是在讨论视频内容，还是集中在求资料、扣关键词一类互动。}
{有价值的评论原文可直接引用（UP 主回复、补充信息、纠错、提问）。}
```

## 写作规则

1. **四项都要有落点**——标题、简介、内容要点、评论情况，一个不省。某项为空就写明为空
2. **评论如实呈现**——差值、刷屏、与内容无关的互动都写出来。评论空荡本身就是情报
3. **分节跟着视频走**——不要机械按时间切，也不要硬套「首先…其次…最后…」
4. **保留具体数字**——时长、数量、耗时、成本、版本号，这些是价值所在
5. **删去**：口头禅、「嗯/啊/这个」、重复句、自我介绍与推广段
6. **不补白**——视频没说的不要加。需要背景时单开一行标注「（补充：…）」
7. **专有名词存疑就标注**——ASR 常把产品名、人名糊掉。听起来像专有名词但无法确定时，
   **保留原音并标明存疑**，同时给出你查到的候选（查过就是查过，没查就说不确定）
8. **长度服从内容**——短视频几百字讲清即可，不要为了显得完整而注水

## 什么时候该改走落盘

用户说了这些（或同义说法）→ 落盘，结构照 `note-template.md`：

- 「整理成笔记」「转成文档」「转成 Markdown」「存下来」「导出」「写成文件」
- 明确给了文件名或保存路径
- 明确说要给谁看 / 要归档 / 要发出去

**拿不准就问一句**：「要我在对话里讲，还是整理成一份文件？」

## 落盘时仍要报告

即便落了盘，对话里依然要给一段简短摘要（这视频是什么、要点几条、评论情况），
再给出文件路径——**不要让用户从零开始自己读文件才知道讲了什么**。

## 反例

- 用户只问「讲了啥」，却建了一个 `.md`——未经要求新建文档
- 报成逐字稿带时间戳——那是转写，不是报告
- 只报内容要点，漏掉简介和评论——四项里少了两项
- 把「AOCI」这类被 ASR 糊掉的名字直接照抄，不标注存疑——把识别错误当成事实传播
- 评论一条不倒、也不概括——「扣关键词」类刷屏要概括，只引用有价值的
