# 读认知与交付协议

本文件管两件事：怎么**读**一份认知索引（含分块），以及上下文被压缩后怎么**重建**认知。

## 一、索引的物理结构

索引由**卷**组成，不是单文件。只读 `aoci.txt` 不算读过整个系统认知。

| 卷 | 职责 |
|---|---|
| **根**（`aoci.txt`） | 声明当前认知集合的组成、依赖与激活入口；**最后发布**，避免残缺资产被当成完整集合 |
| **元**（`aoci.meta.txt`） | 标签字典、条目规则、配额、模型创作约束 |
| **代码**（`aoci.code.txt`） | 代码、测试、配置、文档与运维资产的条目 |
| **数据库**（`aoci.database.txt`） | 可选的表级条目，默认不存在 |

**根 + 元 + 参与的对象卷 = 完整索引（Whole-Index）**。

## 二、一条条目记录什么

每条条目按四个字段组织（FRAS）：

| 字段 | 回答什么 |
|---|---|
| **F — 职责** | 这个对象的核心职责是什么 |
| **R — 关系** | 改动它时必须一起看哪些对象 |
| **A — 契约** | 外部调用方可以依赖什么接口、命令、格式 |
| **S — 隐含约束** | 前三项没覆盖、但影响正确性的重要信息（事务边界、兼容性、失败回退、不可清理的历史分支） |

`S` **不是摘要**，也不重复前三项。它记的是**从代码里读不出来、但搞错就会出错**的东西。

条目还带紧凑标签，给对象坐标（架构层 / 功能域 / 重要度 / 规模）。标签字典由项目自己的元卷定义，
**程序只校验结构与字典，不决定业务语义**。

## 三、读的姿态

- 新会话开始读**一次**完整认知，作为系统级先验
- 只要模型还能可靠使用这份认知，**就不必在每个任务或每次工具调用前重复加载**
- 同一会话内模型按自身状态决定是否重载——**唯一例外是已知的宿主上下文压缩**
- 读了认知 ≠ 不用读源码：认知给全局先验，**源码与测试是实现的真相**

## 四、分块交付与完整确认

认知超过交付块预算时会分块返回：

1. 交付从**第 1 块**开始
2. **沿游标自动读到最后一个分块**
3. 用已交付的完整索引提交**一次确认**
4. **不得**以局部搜索、旧记忆、补读源码或直接打开索引文件来**冒充**完整交付
5. 存在待恢复或不一致快照时**失败关闭**，不混合内容

**不得**用来修补认知的手段（在确认完成前）：记忆、源码、规范文档、直接读 `aoci.txt`、
历史会话、范围视图、搜索结果、单条读取。

**交付大小**：`overview_delivery.chunk_tokens` 是唯一起作用的设置，默认 8000，
有效范围 4000–24000。有些宿主会把过大的工具结果落盘、只把预览放进上下文——
**那对认知交付等于静默失败**；AOCI 声明了单工具结果上限，让宿主为这一个工具抬高阈值。

## 五、上下文压缩后：强制完整重载

**已知发生过压缩时，没有便宜路径。**

1. 如果规则已不可靠，**先重读规则**
2. 用**新的事件 ID** 声明 `context_compaction`
3. 完成**一次普通的完整认知请求**——沿游标到完成、确认交付、提交一次校验
4. **便宜的检查点与认知探针都不能替代**这一步

**压缩交接里能保留什么**：只有回执身份、未完成的写入或恢复状态、以及「立刻重载」的指令。
**不得**保留或摘要完整索引，也不得保留任何条目、分块、校验正文——
复制进交接的索引语义**不能证明**当前模型认知可靠。

**重载之后**：即使校验是部分通过或失败，仍按既有规则继续**绑定源码的任务**，
不自动发起第二次认知请求。

**没有确定性压缩事件的宿主**：模型必须**显式声明**「完整的仓库视图已丢失」。

## 六、认知状态的含义

状态维度是独立的，**不能互相替代**：

| 状态 | 含义 |
|---|---|
| `delivery_verified` | 当前索引已加载且宿主交付已确认；严格校验可能仍未完成 |
| `model_cognition_usable` | 模型对系统框架的了解足以承担当前任务 |
| `strict_attestation_verified` | 索引身份、条目序列、数量与挑战全部严格通过 |
| `governance_aligned` | 索引、基线与治理状态当前一致 |
| `current_system_cognition_reliable` | 模型对**完整当前系统**的图景可无保留地作为系统级先验 |

**只有最后一项为真，才允许无保留地声称「已完整理解当前系统」。**
校验只证明交付覆盖与身份一致，**不表示模型已理解所有可能的未来任务**。

分级标签（`no_cognition` → `index_loaded` → `delivery_verified` → `cognition_verified`
→ `cognition_governed`）不替代上述维度：交付已确认但校验失败，应报为「已加载且交付已验证」，
**不是**「没有系统认知」。

## 七、工具分工

| 类别 | 工具 | 用途 |
|---|---|---|
| **读** | `aoci_rules` / `aoci_overview` / `aoci_get_entries` / `aoci_search` | 规则、完整认知、按条读、检索 |
| **维护** | `aoci_maintain` / `aoci_update_entry` / `aoci_remove_entry` | 维护流程、更新条、移除条 |
| **证据** | `aoci_header` / `aoci_report` | 头信息、报告 |

读类工具结束时会附一行建议状态（形如 `cognition: refresh_status=…`），
由进程内会话事实算出、**零扫描成本**。它的默认含义是「**不**需要重新召回」，
只在有真实信号时才升级建议。
